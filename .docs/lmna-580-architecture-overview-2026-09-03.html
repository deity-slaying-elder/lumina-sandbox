BLUF

The TCM automation that failed on bulk loads is now Apex, tested end to end, switchable from Setup like the flows were, and ready for production on your go.

  • Root cause fixed and proven: loads that died at 13 records per patient now save at 60+

Background
Lumina's discharge, admission and TCM automation lived in 26 record-triggered flows. Flow governor limits rolled back entire bulk loads, and logic could only change one flow version at a time.
Ask
Chose to convert all of it to Apex on a metadata-driven trigger framework, keeping the business's ability to switch any behaviour off without a deploy.
Status
Complete in the dev sandbox. Production deploy packaged with a validated rollback; blocked only on sign-offs (section 06).

01Why: the failure that raised the ticket

Flows updated the patient once per record; Salesforce caps that at 12 per save. Record 13 threw DUPLICATE_VALUE and rolled back the whole load.

BEFORE

One flow interview per record

Insert 20 discharges for one patient, single save
▼ fires 20 flow interviews
Interview 1 → update Patient  ·  Interview 2 → update Patient  ·  …  ·  Interview 13 → ✕ DUPLICATE_VALUE (12 allowed)
Whole save rolls back. No partial success, no visibility into which record was "the problem" - there wasn't one.
AFTER

One Apex pass, one write per patient

Insert 20 discharges for one patient, single save
▼ fires the trigger once, in bulk
Action collapses all patient writes into one DML row - the ceiling no longer applies
Verified live at 60 records for one patient and 200 mixed records across 20 patients. Zero governor errors.

02The runtime: how a save flows through the new architecture

One trigger per object, zero logic in it. Behaviour is declared as ordered Trigger Action metadata records. Dispatch path for the busiest object:

Save path · Admission/Discharge record inserted

AdmissionDischargeTrigger - the only trigger on the object
▼ ① incident lever checked first
TriggerContext.isBypassed - org-wide kill switch (Trigger_Bypass records). One checkbox in Setup silences every converted trigger during an incident. No deploy.
▼ ② framework reads the action registry
MetadataTriggerHandler - queries Trigger_Action__mdt for this object + context, honours per-action Bypass Execution, executes in Order__c sequence
▼ ③ actions run in declared order, each bulk-safe
AdmissionDischargeSetLatestOrder 10 · stamps Latest Admission/Discharge on the patient
AdmissionDischargeCreateEpisodeOrder 20 · opens a Community Episode, reclaims quiet patients
DischargeSendSmsOrder 30 · decides who gets the discharge text
▼ ④ side effects cascade through the same discipline
PatientTrigger (before update)reclaim, consent stamp, program copy, name, state - ordered 1–5
CommunityEpisodeTriggernames the episode, links it back to the patient
DischargeSendSmsQueueableasync Twilio delivery - callouts cannot run inside a save
A1
Actions run as the system, like the flows did. User-mode enforcement silently drops writes for restricted profiles - a lost TCM timestamp is invisible lost billing evidence. A permission suite runs the cascade as the most restricted profile and fails if this regresses.
A2
SMS delivery is async - the only intended behaviour change. Salesforce forbids callouts inside a save. The decision stays in the save; delivery follows seconds later. Live testing showed Twilio deferred internally even under the flow, so the practical delta is near zero.
A3
Fidelity over cleverness. Two known flow defects were reproduced on purpose so the port is provably identical; each fix ships as its own reviewed change. One "improvement" that diverged from flow behaviour was caught by live testing and removed.

04The control plane: flow-like switching, kept

The real requirement was keeping flow-style on/off control. Three levers, all verified live both directions:

Per actionSETUP, LIVE

Bypass Execution checkbox on any Trigger Action record. One behaviour off, everything else untouched. The flow-deactivation equivalent.

Per objectSETUP, LIVE

Bypass on the object's Trigger Setting record silences all actions for that object.

Org-wide kill switchSETUP, LIVE

All_Triggers bypass halts every converted trigger at once. The incident lever, checked before anything runs.

Rollback per behaviour: re-activate the retained flow version, tick the action's bypass. Two checkboxes, no deploy.

07Path to production

P1
Deploy package prepped: classes, triggers, framework, metadata types, field + admin permissions, flow deactivations. Custom metadata records go in through the Apex Metadata API - standard record deploys of these types fail with an unhelpful platform error (root cause found: a 40-character name limit reported as UNKNOWN_EXCEPTION).
P2
Rollback validated in advance: per-behaviour rollback is two checkboxes; full rollback is the pre-validated revert package with a Quick Deploy id.
P3
Open sign-offs: async SMS delivery (business), field visibility for two currently-invisible patient fields (business), deploy window (engineering).
