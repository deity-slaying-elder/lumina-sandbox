Code-gated report access: components, screens, sequence

Real class and field names, the screens the recipient sees, the exact order of checks, and what production needs before deploy. Blue is new or changed. Built and live-tested in the lumDev sandbox on 15 September 2026; 142 Apex tests green across 13 classes.

01

Components

The batch and the PDF render are untouched. The publisher and the email builder change. Everything on the site is new. The public file link (ContentDistribution) is gone, so the site page is the only door.

02

Schema changes

New fields on Readmission_Report_Link__c, one row per recipient per report, and one new child object for the access log. Nothing stores the raw token or the raw code.

FieldTypeHolds
Access_Token_Hash__c Text(64), unique, external id, case-sensitive SHA-256 of the 256-bit token in the URL (Crypto.generateAesKey(256), hex). The raw token exists only in the recipient's email.
Content_Version_Id__cText(18) The stored PDF the row points at. The purge job reads this.
Code_Hash__cText(64) SHA-256 of token + ':' + code. Salted with the token, so a database read alone cannot be tested against a code offline. Cleared when the code is used.
Code_Expires_At__c, Code_Sent_At__c DateTime The 10-minute code life, and the 60-second resend throttle.
Codes_Sent__cNumber(2,0) Five per link, then the row is Locked.
Failed_Attempts__cNumber(2,0) Reset on a correct code. Five locks the row.
Unlocked_Until__cDateTime Set to now + 10 minutes by a correct code. The REST endpoint serves only inside it.
Closed_Reason__cPicklist, 2 new values Adds Locked and Superseded to the existing View limit reached and Manually revoked.
Distribution_Id__cText, legacy Phase one only. Kept for old rows, no longer written.
TCM_Report_Config__mdt.Portal_Base_Url__cURL, optional Override for the site base. When blank the URL is derived from the Site record and its domain, so nothing is hardcoded per org.

Unchanged and still in use: Opens__c, Downloads__c, First_Opened_At__c, Last_Activity_At__c, Expires_At__c, Closed_At__c, Recipient_Email__c, Intended_For__c, Recipient_Role__c, Report_Date__c.

New object Readmission_Report_Access__cTypeHolds
ObjectMaster-detail child of Readmission_Report_Link__c, relationship Access_Log One record per event on a link. Label "Readmission Report Access". Written by TCMReadmissionGateService.log() in system mode. Never holds a code or a token.
Event__cPicklist Code sent, Code throttled, Code refused, Wrong code, Code expired, Locked, Opened, View limit reached, PDF fetched, Downloaded, Fetch refused.
IP_Address__cText(45) From X-Salesforce-SIP, falling back to True-Client-IP, then the first X-Forwarded-For hop. IPv6 fits.
User_Agent__cText(255)The browser or client string.
Occurred_At__cDateTimeWhen the event happened.
Detail__cText(255) Such as "Attempt 3 of 5", "Open 2 of 10", "Download 1", "Outside the unlock window".

Staff read the log through the TCM_Readmission_Reports and TCM_Readmission_Report_Operator permission sets. The guest has no access to it. A made-up token has no row to log against and leaves no trace, by design.

04

Request sequence

The four entry points on TCMReadmissionGateService, in the order a reader hits them. Every one starts by resolving the token; a miss at any guard returns the unavailable outcome and nothing below it runs. The page controller and the REST endpoint first pass the request headers in through setCaller(headers), so every log row below carries the caller's IP and user agent.

01
look(token). On page load. Shape-check the token, hash it, find exactly one live row. Decides which of the four states to render. No writes.
// find(): 64 hex chars or nothing
String hash = TCMReadmissionAccessToken.hashToken(rawToken);
[SELECT ... FROM Readmission_Report_Link__c
 WHERE Access_Token_Hash__c = :hash LIMIT 1]
// isLive(): Closed_Reason__c == null AND Expires_At__c > now
Unlocked_Until__c > now → report · code outstanding → verify · else request
02
requestCode(token). Throttle, cap, sandbox guard, then mint, email and store the hash. The code goes to Recipient_Email__c only.
Code_Sent_At__c + 60s > now → refuse, no write
Codes_Sent__c >= 5 → close('Locked')
isSandbox() && !sandboxMayReceive(email) → refuse, no email
code = mintCode(); sendCode(row, code)
Code_Hash__c = hashCode(token, code) // sha256(token + ':' + code)
Code_Expires_At__c = now + 10 min; Codes_Sent__c++
03
verify(token, code). Constant-time compare. Wrong is a strike; expired is not. Right counts the open, checks the cap, and opens the window.
!looksLikeCode → "Enter the six-digit code", no strike
!codeOutstanding → "That code has expired", no strike
!matches(Code_Hash__c, hashCode(token, code)) → Failed_Attempts__c++
  5 → close('Locked') else "N attempts left"
Opens__c >= maxOpens() → close('View limit reached')
Opens__c++; First_Opened_At__c ??= now; Last_Activity_At__c = now
Unlocked_Until__c = now + 10 min; Code_Hash__c = null; Failed_Attempts__c = 0
04
serve(token, download). Called by the REST endpoint for the <object>, the new tab and the Download button. Inline fetches add no opens; only a correct code does.
// GET /services/apexrest/tcm/report?t=..[&dl=1]
!isLive || Unlocked_Until__c <= now || no Content_Version_Id__c
  → 404 "This report is no longer available."
[SELECT VersionData FROM ContentVersion WHERE Id = :versionId]
dl=1 → Downloads__c++, Content-Disposition: attachment
Cache-Control: no-store, private · X-Content-Type-Options: nosniff
05
log(event, detail). Called from every branch above that touches a real row. Writes one Readmission_Report_Access__c child in system mode, with time, IP and user agent. Never a code, never a token.
requestCode → Code sent | Code throttled | Code refused | Locked
verify → Wrong code "Attempt 3 of 5" | Code expired | Locked
         Opened "Open 2 of 10" | View limit reached
serve → PDF fetched | Downloaded "Download 1" | Fetch refused "Outside the unlock window"
// IP: X-Salesforce-SIP, else True-Client-IP, else first X-Forwarded-For hop
Reissue. The Resend button (TCMReadmissionResend) and the daily job both call TCMReadmissionLinkPublisher, which mints a new token and closes the previous live link to the same address for the same facility with Closed_Reason__c = 'Superseded'. Only the newest link works.
05

Guest user reach, in full

This table is the security answer. The guest holds no object and no field permission. The service runs in system mode and can name a row only by presenting the token whose hash it stores.

GrantGuest accessNote
Permission set TCM_Readmission_Portal_Guest Assigned to the site guest user Classes: TCMReadmissionGateController, TCMReadmissionGateService, TCMReadmissionReportGateApi, TCMReadmissionAccessToken, TCMReadmissionPortal, TCMReportConfig. Pages: TCMReadmissionReportGate, TCMReadmissionPortalError. The guest profile TCM Readmission Portal Profile carries the same page and class access.
Objects and fieldsNone No CRUD, no FLS on any object. Readmission_Report_Link__c and ContentVersion are reached by the without-sharing service only, and only for the row that matches the token hash.
Facility__c, Patient__c, Hospital_Admission__c None The service never queries them. The facility name comes through the link row's lookup, inside the same query.
Readmission_Report_Access__cNone Written by the service in system mode only. Staff read it through TCM_Readmission_Reports and TCM_Readmission_Report_Operator.
Internal page TCMReadmissionReportPdfNot exposed The page that renders patient data stays inside the org and runs as the job.
Site settingsLocked down No standard pages, lookups, search or home page. Clickjack protection same-origin only. Content sniffing and XSS protection on. Aura requests off.
Verified by test: TCMReadmissionGateServiceTest includes a run of the whole flow as the real site guest user under System.runAs. In a sandbox the service also refuses to email a code to any address that is not on the sandbox redirect list, so a hand-made row cannot reach a real facility.
06

Production prerequisites

The site is built and tested in lumDev. Production needs these five things, in this order.

#StepWho
01 Register Salesforce Sites once in production. Setup > Sites > accept the terms > Register My Salesforce Site Domain. The domain data-efficiency-9627.my.salesforce-sites.com already exists. Until this is done every page shows the maintenance page. Lumina admin
02 Change the subdomain before the production deploy. In sites/TCM_Readmission_Portal.site-meta.xml, change data-efficiency-9627--partialsb to data-efficiency-9627. Production links will then read https://data-efficiency-9627.my.salesforce-sites.com/report?t=… Propela
03 Assign the permission set TCM_Readmission_Portal_Guest to the site guest user after the site is created. Propela
04 Allow the org-wide address tcm@luminacare.com for all profiles, or for the guest profile, so the code email comes from it. Otherwise the code email is sent as the site guest user, which works but reads worse. Lumina admin
05 Deploy is a human action. Propela prepares the files and the exact command; a person runs it against production after Lumina's go-ahead. Propela
