The new model, in one page

The report link now opens a page we host on a Salesforce site. That page emails a one-time code to the address the link was issued to, and shows the report only after the code is entered. Built and tested in the sandbox on 15 September 2026.

The whole change

Phase one
The email carries a link. Anyone holding that link opens the report, nothing else asked.
Now
The email carries a link and nothing secret. The link opens our page, the page emails a six-digit code to the address on file, and the report appears only after that code is entered. The code works for 10 minutes.

How it works

Inside Salesforce already built, keeps working
01
The job runs

8am on weekdays, one facility at a time.

02
The report is built

One PDF per facility, filed on the facility record.

03 · new
A private link is made

One per recipient. We keep a scrambled fingerprint of it, never the link itself. Any older live link to the same person is closed.

04
The email goes out

Administrator, or director of nursing. A count, a button, and how to get a code. No patient data and no code in it.

the email leaves Salesforce
Outside · the facility administrator, no login the new part
05
They click the link

Our page shows the facility name, the report date, and the masked address the code will go to. Nothing from the report.

06 · new
They ask for a code

One click. A six-digit code is emailed to the address on file. It works for 10 minutes.

07 · new
They enter the code

Right code, the report opens. Five wrong codes, or five codes requested, and the link locks for good.

08
The report opens

The view is logged against that person. The PDF stays open for 10 minutes, then a new code is needed.

An expired link, a locked link, a used-up link and a made-up link all get the same page: This report is no longer available. A guesser learns nothing from the wording. The page and the email both say to reply to the email for a new link. Every step on a link, from the code being sent to the report being opened or downloaded, is logged with the time, the IP address and the browser, so a disclosure can be traced to a device as well as to a mailbox.

What was built

One page on a Salesforce site
Salesforce Sites, guest access, no login

A request button, a code box, then the report. No account for the facility to manage, and no per-facility licence.

A private link per recipient
the recipient record we already keep

Eight fields added: fingerprints of the link and the code, the timers, and the counters. Nothing stores the link or the code in the clear.

A locked-down visitor profile
page and code access only

The visitor can reach the page and the service behind it, and nothing else. No records, no fields. Listed below.

For Chris

His concernAnswer
People guessing other facilities' links Not possible. The link is 64 random characters, and there is no public file link at all.
A link on its own is not enough Agreed, and done. A link with no code opens nothing but a request button. That covers browser history, a pasted chat message, a screenshot, a proxy log.
A forwarded email Covered. The code goes to the address the link was issued to, so someone holding a forwarded email can only get in if they also control that mailbox. This is the gap the earlier same-email PIN idea left open.
Someone tries codes until one works Five wrong codes lock the link. A code has a million possibilities and lasts 10 minutes.
